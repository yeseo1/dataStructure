# 과제 07: 인접 행렬과 인접 리스트의 성능 비교

## 실행 방법

Windows에서는 `hw7.exe`로 실행할 수 있다. 인자가 없으면 현재 시각을 난수 시드로 사용하고 숫자 인자를 주면 같은 환경에서 실험을 재현한다.

## 동일한 그래프 생성과 실험 순서

정점은 0~99이며 가능한 무방향 단순 간선은 `100 × 99 / 2 = 4950`개다. `u < v`인 모든 쌍을 임시 배열에 만들고 부분 Fisher-Yates 섞기를 통해 희소 그래프에는 100개, 밀집 그래프에는 4000개를 선택한다. 자기 간선과 중복 간선은 후보 구성 단계부터 제외된다. 선택한 간선을 같은 순서로 행렬과 연결 리스트에 추가하므로 두 표현의 간선 집합은 동일하다.

각 그래프에서 다음 순서로 실험한다.

1. 생성 직후, 간선 수가 100 또는 4000일 때 그래프 표현 메모리를 계산한다.
2. 선택하지 않은 후보 중 하나를 골라 두 표현에 같은 간선을 추가한다.
3. 원래 있던 간선 중 하나를 골라 두 표현에서 삭제한다. 방금 추가한 간선을 바로 삭제하는 실험은 아니다.
4. 임의의 서로 다른 정점 쌍을 두 표현에서 조회한다.
5. 임의의 동일 정점을 골라 양쪽 표현의 인접 정점을 출력한다.

추가 후에는 간선이 한 개 늘고 삭제 후에는 원래 개수로 돌아온다. 연결 확인과 인접 정점 출력은 삽입·삭제가 완료된 동일한 상태를 대상으로 한다. 초기 생성, 연산 대상 선택 및 검증 비용은 측정 연산의 비교 횟수에 포함하지 않는다. 출력된 정점 쌍과 정점 번호로 각 실험의 대상을 확인할 수 있다.

## 메모리 측정 범위

- 행렬: `sizeof(Matrix)`. `int cells[100][100]`과 정점·간선 수 관리 변수를 포함한다.
- 리스트: `sizeof(List) + 2E × sizeof(Link)`. 정점별 시작 포인터 100개, 정점·간선 수 관리 변수, 각 무방향 간선의 양 끝에서 사용하는 연결 노드 두 개를 포함한다.

`sizeof`에는 구조체 정렬을 위한 패딩이 포함된다. 임시 간선 후보 배열, 난수 상태, 측정·검증 변수, 프로그램 코드, 함수 호출 스택 및 메모리 할당기의 내부 관리 공간은 제외한다. 리스트 노드에 요청한 할당 크기를 합산하는 방식이며 프로세스 전체 메모리 측정은 아니다.

행렬 원소 자료형은 `int`로 고정하였다. `char`나 비트 배열을 쓰면 행렬 메모리는 달라지므로 아래의 공간 비교는 이 구현과 실행 환경을 기준으로 한다.

## 비교 횟수 기준

이전 탐색 과제의 연산자 실행 횟수와 달리 이번 과제는 확인한 행렬 원소 또는 리스트 노드 하나당 1회로 센다. 포인터의 NULL 검사, 인덱스 검사, 쓰기·연결 변경·해제는 세지 않는다.

| 연산 | 행렬 | 연결 리스트 |
|---|---|---|
| 삽입 | `matrix[u][v]` 존재 확인 1회, 양쪽 칸에 기록 | u의 리스트에서 중복 확인 후 양쪽 리스트 맨 앞에 추가 |
| 삭제 | 존재 확인 1회 후 양쪽 칸을 0으로 변경 | u에서 v를 찾은 횟수와 v에서 u를 찾은 횟수의 합 |
| 연결 확인 | 해당 칸 확인 1회 | u의 리스트에서 발견할 때까지, 없으면 끝까지 확인 |
| 인접 정점 출력 | 해당 행 100칸 확인 | 해당 정점의 리스트 노드 전부 확인 |

무방향 그래프의 대칭성을 유지하므로 삽입 중복 확인과 연결 확인은 한쪽만 검사하면 된다. 리스트 삭제는 실제 두 연결 노드의 위치를 찾아야 하므로 양쪽의 탐색을 모두 센다. 행렬은 반대쪽 칸의 주소도 바로 계산할 수 있어 추가 탐색 없이 두 칸을 지운다.

리스트는 앞에 삽입하는 비정렬 연결 리스트다. 인접 정점 출력 순서는 행렬과 다를 수 있지만 출력하는 정점 집합은 같다. 빈 리스트를 순회하면 노드를 하나도 확인하지 않으므로 비교 횟수는 0이다.

visual studio에서 실행하였다. 전체 결과는 [result.txt](result.txt)에 기록하였다. `sizeof(int)=4`, 포인터 크기는 8바이트, `sizeof(Link)=16`바이트였다.

| 경우 | 메모리(Byte) | 삽입 비교 | 삭제 비교 | 연결 확인 비교 | 인접 정점 출력 비교 |
|---|---:|---:|---:|---:|---:|
| 희소 - 행렬 | 40,008 | 1 | 1 | 1 | 100 |
| 희소 - 리스트 | 4,008 | 2 | 2 | 2 | 1 |
| 밀집 - 행렬 | 40,008 | 1 | 1 | 1 | 100 |
| 밀집 - 리스트 | 128,808 | 84 | 50 | 35 | 80 |

### 희소 그래프 분석

희소 그래프에서는 행렬이 `100 × 100 × 4 + 8 = 40008`바이트를 사용하였다. 리스트는 시작 포인터와 관리 변수에 808바이트, 간선 노드 200개에 `200 × 16 = 3200`바이트를 사용하여 총 4,008바이트였다. 따라서 리스트가 36,000바이트 적게 사용하였다. 행렬은 간선이 없는 위치도 저장하지만 리스트는 존재하는 간선만 저장하기 때문이다.

추가한 간선은 `(47,79)`이며 정점 47의 기존 리스트 노드 2개를 확인하였다. 삭제한 `(23,66)`은 양쪽 리스트에서 각각 첫 노드를 찾아 총 2회였다. `(81,8)`의 연결 확인은 실패했으며 정점 81의 리스트 2개를 끝까지 확인하였다. 세 연산 모두 행렬은 해당 원소 한 개만 확인하였다.

인접 정점 출력 대상은 19였고 이웃은 91 하나였다. 행렬은 100칸을 모두 검사했지만 리스트는 1개만 확인하였다. 이번 희소 그래프에서는 리스트의 메모리 절감과 이웃 출력의 이점이 컸고 삽입·삭제·연결 확인의 비교 횟수 차이는 작았다.

### 밀집 그래프 분석

행렬 메모리는 간선 수와 관계없이 40,008바이트였다. 리스트는 간선 노드가 8,000개여서 `808 + 8000 × 16 = 128808`바이트였다. 행렬보다 88,800바이트 많다. 높은 밀도에서는 각 간선마다 정점 번호뿐 아니라 다음 노드 포인터와 구조체 패딩을 저장하는 비용이 커진다.

`(22,88)` 삽입에서는 정점 22의 리스트 84개를 확인하였다. `(2,84)` 삭제에서는 양쪽 노드 위치를 찾는 데 총 50회, `(35,96)` 연결 확인은 성공할 때까지 35회가 필요했다. 행렬은 모두 1회였다. 특히 없는 간선 삽입의 중복 확인은 리스트 전체를 보므로 높은 차수가 그대로 비용으로 이어졌다.

정점 0의 이웃은 80개였다. 인접 정점 출력은 행렬 100회, 리스트 80회로 리스트가 20회 적었지만 희소 사례의 100회 대 1회에 비해 차이가 작았다. 리스트 출력 순서는 삽입 순서 때문에 다르지만 행렬과 같은 80개 정점을 출력하였다. 이번 밀집 사례에서는 메모리와 간선 질의·변경의 비교 비용에서 행렬이 유리했고 이웃 출력에서는 리스트의 이점이 줄어들었다.

## 그래프 밀도에 따른 해석

희소 그래프의 밀도는 `100 / 4950 ≈ 2.02%`, 평균 차수는 `2E/V = 2`이다. 밀집 그래프의 밀도는 `4000 / 4950 ≈ 80.81%`, 평균 차수는 80이다. 리스트 저장 공간과 순회 길이는 실제 간선 수 및 정점 차수에 따라 증가하지만 행렬 저장 공간과 한 행을 확인하는 비용은 간선 수와 무관하다.

존재하지 않는 간선을 삽입할 때 중복 검사를 포함하므로 리스트는 해당 정점의 차수만큼 확인한다. 중복 검사를 생략하고 맨 앞에 붙이는 작업만 측정한 O(1) 삽입과는 구분해야 한다. 삭제는 두 정점 차수에 비례하는 탐색이 필요할 수 있다. 연결 여부 확인은 행렬이 항상 O(1)이고 리스트는 최악 O(deg(u))이다.

인접 정점 전체를 구하는 작업은 행렬 O(V), 리스트 O(deg(u))이다. 따라서 연결 여부 질의가 많고 간선이 조밀한 그래프는 행렬이 적합하며 간선이 적고 이웃 순회가 많은 그래프는 리스트가 적합하다. 밀집 그래프에서도 특정 정점의 이웃을 전부 출력하는 비교 횟수는 리스트가 더 작을 수 있으므로 한 연산의 결과만으로 모든 성능을 판단하지 않는다.

각 연산은 그래프별로 한 번씩 측정한다. 선택된 정점의 차수와 리스트 내 위치에 영향을 받는 단일 표본이며 평균 실행 시간의 측정은 아니다. 실제 시간에는 메모리 접근, 할당·해제, 캐시 등의 영향도 있으나 이번 과제에서는 지정된 비교 횟수만 분석한다.

## 검증

제출 프로그램과 테스트를 경고 없이 컴파일하였다. 프로그램은 생성 직후, 삽입 직후, 삭제 직후에 다음을 확인한다.

- 모든 정점 쌍에서 행렬과 리스트의 연결 상태가 동일한지
- 자기 간선·중복 리스트 노드가 없으며 무방향 대칭성이 유지되는지
- 간선 수가 원래 E, 삽입 후 E+1, 삭제 후 E인지

별도 테스트에서는 작은 그래프의 알려진 비교 횟수, 역방향 중복 삽입 거부, 자기 간선 거부, 기존·없는 간선 삭제를 검증하였다. 또한 시드 0~4로 희소·밀집 그래프 총 10개를 실행하여 위 검증을 모두 통과하였다.
