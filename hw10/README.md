# 과제 10: 정렬 알고리즘의 성능 및 안정성 비교

## 실행 방법과 측정 기준

시드를 생략하면 현재 시각을 사용한다. 같은 실행 환경과 시드에서는 결과를 재현할 수 있지만 C 라이브러리의 `rand()` 구현이 다르면 난수와 측정 결과도 달라질 수 있다. 실행 중 10회마다 진행 상황을 표준 오류로 출력한다.

각 데이터는 `(key1, key2, order)` 구조체이다. 두 키는 각각 0~1,000,000에서 생성하고 중복을 허용한다. 정렬 기준은 key1만 사용하며 key2와 원래 순서 번호 order는 함께 이동한다. `RAND_MAX`가 32767인 환경에서도 전체 범위의 값이 나오도록 난수를 조합하고 나머지 연산의 편향을 줄이기 위해 초과 구간을 재추출한다.

매회 새로운 데이터 10,000개를 생성하여 동일한 복사본을 선택 정렬, 일반 버블 정렬, 조기 종료 버블 정렬, 삽입 정렬에 제공한다. 이를 100회 반복한다. 일반 버블과 조기 종료 버블은 같은 함수에서 조기 종료 여부만 다르게 설정한다. 매 순회가 끝나면 다음 순회의 끝 위치를 한 칸 줄이는 조건도 동일하다.

- 비교: 실제 수행한 key1 비교마다 1회. 삽입 정렬에서 이동하지 않기로 결정한 마지막 비교도 포함한다. 인덱스 및 반복 조건 검사는 제외한다.
- 이동: 구조체 전체를 대입할 때마다 1회. 교환은 3회, 삽입 정렬은 임시 저장·각 이동·최종 저장을 각각 센다. 선택 정렬은 최소 위치가 현재 위치와 같으면 교환하지 않는다.
- 생성, 원본 복사, 상태별 입력 준비, 결과 검증은 집계에서 제외한다. 합계가 32비트 범위를 넘을 수 있으므로 `uint64_t`를 사용한다.
- 각 결과의 오름차순 여부, 원래 데이터의 중복·누락 여부, 두 키의 보존을 검사한다. 같은 key1 사이의 order가 증가하는지 확인하여 해당 입력에서의 안정성도 검사한다.

## 상태별 입력 구성

무작위 상태는 100회 평균을 사용한다. 나머지 세 상태는 첫 번째 무작위 실험의 동일한 10,000개 데이터를 바탕으로 각각 1회 측정한다.

1. 정렬 상태: key1 기준 오름차순 정렬.
2. 역순 상태: 정렬 상태를 전체 역순으로 배치.
3. 부분 정렬 상태: 정렬된 배열에서 `(0,1), (2,3), …, (9998,9999)`의 5,000개 인접 쌍 중 100쌍을 무작위로 중복 없이 선택하여 교환.

부분 정렬 방식은 AI(Codex)의 도움으로 설계했다. 교란 정도를 명확히 설명할 수 있도록 서로 겹치지 않는 인접 쌍을 선택했다. 200개 레코드, 즉 전체의 2%가 한 칸씩 이동한다. 같은 키끼리 교환하면 순서 위반은 생기지 않으므로 프로그램은 실제 엄격한 역전 수를 따로 출력한다. 이는 이동 거리가 작은 국소 교란 실험이며, 먼 위치끼리 교환하거나 긴 구간을 섞은 모든 부분 정렬 입력을 대표하지는 않는다. 각 상태 구성 후 order를 다시 부여하여 **해당 정렬 직전** 상대 순서를 기준으로 안정성을 판단한다.

## 실제 실행 결과와 분석

visual studio로 실행했다. 전체 출력은 [result.txt](result.txt)에 저장했다. 무작위 100회 모두 네 구현의 정렬 및 레코드 보존 검사를 통과했다. 아래 수치는 실행시간이 아니라 과제에서 정의한 연산 횟수이다.

### 무작위 100회

| 알고리즘 | 총 비교 | 평균 비교 | 총 이동 | 평균 이동 |
|---|---:|---:|---:|---:|
| 선택 | 4,999,500,000 | 49,995,000.00 | 2,997,063 | 29,970.63 |
| 일반 버블 | 4,999,500,000 | 49,995,000.00 | 7,505,720,550 | 75,057,205.50 |
| 조기 종료 버블 | 4,998,533,773 | 49,985,337.73 | 7,505,720,550 | 75,057,205.50 |
| 삽입 (`>`) | 2,502,905,881 | 25,029,058.81 | 2,503,906,650 | 25,039,066.50 |

선택 정렬과 일반 버블은 입력 상태와 무관하게 `n(n-1)/2 = 49,995,000`번 비교한다. 선택 정렬은 최소값을 찾은 뒤 최대 한 번만 교환하므로 이동은 평균 약 3만 회였다. 반면 버블은 순서가 뒤집힌 쌍을 인접 교환으로 해소한다. 역전 하나당 3회 이동하여 평균 이동이 약 7,506만 회에 달했다.

조기 종료 버블은 일반 버블보다 총 966,227회, 평균 9,662.27회(약 0.0193%) 적게 비교했다. 무작위 입력에는 왼쪽으로 멀리 이동해야 하는 작은 값이 있어 대부분의 순회가 필요했다. 마지막의 교환 없는 순회 이후만 생략하므로 절감 효과는 작았다. 실제 교환은 동일하므로 이동 횟수는 정확히 같았다.

삽입 정렬은 필요한 만큼만 앞부분을 검사해 평균 비교가 약 2,503만 회로 선택·일반 버블의 약 절반이었다. 버블의 3회 대입 교환 대신 역전마다 기존 레코드를 한 칸 이동시키므로 이동량도 훨씬 작았다. 다만 무작위 입력에서는 많은 이동이 필요하여 여전히 이차 시간 특성을 보인다. 선택 정렬은 비교가 많아도 이동은 적으므로 비교와 이동 중 어떤 비용이 큰지에 따라 평가가 달라진다.

### 이미 정렬된 입력

| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 | 49,995,000 | 0 |
| 일반 버블 | 49,995,000 | 0 |
| 조기 종료 버블 | 9,999 | 0 |
| 삽입 (`>`) | 9,999 | 19,998 |

선택과 일반 버블은 전체 비교를 계속한다. 조기 종료 버블은 첫 순회에 교환이 없어 즉시 끝나며 삽입 정렬도 각 원소당 직전 값과 한 번 비교한 후 멈춘다. 삽입 정렬의 이동이 0이 아닌 이유는 각 단계에서 임시 변수 저장과 최종 대입을 실행하기 때문이다. 따라서 `2(n-1)=19,998`회다. 두 구현의 최선 비교 복잡도는 O(n)이다.

### 역순 입력

| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 | 49,995,000 | 15,084 |
| 일반 버블 | 49,995,000 | 149,984,826 |
| 조기 종료 버블 | 49,995,000 | 149,984,826 |
| 삽입 (`>`) | 49,995,000 | 50,014,940 |

역순에서는 거의 모든 서로 다른 키 쌍이 뒤집혀 있다. 버블은 계속 교환하므로 조기 종료로 줄어드는 비교가 없었고 이동은 무작위 평균의 약 두 배였다. 실제 엄격한 역전 수는 `149,984,826 / 3 = 49,994,942`개다. 동일 키 쌍 58개는 교환하지 않아 모든 키가 서로 다른 경우보다 작다. 삽입 정렬의 이동은 이 역전 수에 임시 저장·최종 대입 19,998회를 더한 50,014,940회와 일치한다. 선택은 떨어진 위치끼리 한 번에 교환하므로 이동량이 상대적으로 작지만 비교 횟수는 줄어들지 않았다.

### 부분 정렬 입력

| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 | 49,995,000 | 300 |
| 일반 버블 | 49,995,000 | 300 |
| 조기 종료 버블 | 19,997 | 300 |
| 삽입 (`>`) | 10,099 | 20,098 |

이번 실행에서는 선택한 100쌍 모두 서로 다른 키여서 정확히 100개의 역전이 생겼다. 선택과 두 버블의 교환은 100번, 이동은 300회였다. 일반 버블은 복구 뒤에도 모든 순회를 수행하지만 조기 종료 버블은 첫 순회에서 역전을 복구하고 두 번째 순회에서 교환이 없음을 확인해 `9,999 + 9,998 = 19,997`번 비교로 끝났다. 삽입 정렬은 기본 비교 9,999회에 역전 해소 비교 100회를 더한 10,099회, 기본 이동 19,998회에 이동 100회를 더한 20,098회를 사용했다.

따라서 이번처럼 조금씩만 어긋난 입력에서는 삽입 정렬과 조기 종료 버블이 이미 정렬된 상태의 이점을 활용했다. 선택 정렬과 일반 버블은 이동량은 줄어도 비교량은 일정했다. 입력 상태를 고려하지 않고 무작위 평균만으로 모든 상황의 우열을 판단해서는 안 된다.

## 안정성 검증

별도 중복 키 입력은 다음과 같다. `#` 뒤 번호는 원래 순서이며 정렬에 사용하지 않는다.

```text
(527,100,#0) (527,200,#1) (125,300,#2) (892,400,#3)
```

안정 정렬 결과에서는 key1=527인 데이터가 #0, #1 순서를 유지해야 한다. 선택 정렬과 삽입 정렬의 `>=` 변형은 이 입력에서 #1, #0 순서를 만들고, 두 버블 정렬과 `>` 삽입 정렬은 #0, #1을 유지한다.

실제로 출력된 결과는 다음과 같다.

```text
선택, 삽입(>=): (125,300,#2) (527,200,#1) (527,100,#0) (892,400,#3)
두 버블, 삽입(>): (125,300,#2) (527,100,#0) (527,200,#1) (892,400,#3)
```

무작위 실험에서도 선택 정렬은 100회 모두 같은 키의 순서 위반이 관찰됐고, 두 버블과 `>` 삽입 정렬은 100회 모두 순서를 유지했다.

- 선택 정렬: 첫 단계에서 최소값 125와 첫 527을 멀리 교환하면서 첫 527이 두 번째 527 뒤로 이동한다. 따라서 같은 값을 직접 비교해 교환하지 않아도 불안정할 수 있다.
- 버블 정렬: 인접한 값이 엄격하게 클 때만 교환한다. 같은 키끼리는 서로 지나가지 않으므로 안정적이다. 조기 종료는 불필요한 비교를 생략할 뿐 이 성질을 바꾸지 않는다.
- 삽입 정렬 `>`: 기존 값이 더 클 때만 오른쪽으로 이동한다. 같은 키의 기존 데이터 뒤에 새 데이터를 넣어 상대 순서를 유지한다.
- 삽입 정렬 `>=`: 같은 키의 기존 데이터까지 오른쪽으로 밀어 새 데이터를 앞에 넣으므로 같은 키의 상대 순서가 뒤집힌다. key1 오름차순 정렬 자체는 여전히 올바르다.

특정 입력에서 순서가 유지되었다고 해서 알고리즘 자체가 안정적인 것은 아니다. 선택 정렬의 불안정성은 위 반례로 확인하며 안정적인 구현들은 동작 원리와 실행 검증을 함께 근거로 판단한다.

## 추가 검증 실행

키가 0, 1, 2인 길이 5 입력 243개 모두에 5가지 변형을 적용한다. 정렬과 데이터 보존, 안정적 변형의 상대 순서, 역전 수를 이용한 이동 횟수, 선택·일반 버블의 비교 횟수를 검사한다. 별도로 정렬된 작은 입력의 정확한 비교·이동 횟수도 확인한다.

실제 검증 결과: 243 × 5 = 1,215개 정렬 검증 및 별도 계수·안정성 검사 통과. 본 프로그램의 무작위 100회와 세 상태별 검사도 모두 PASS로 종료했다.
