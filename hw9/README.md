# 과제 09: 모든 정점 쌍의 최단경로

## 실행

`hw9.exe`를 실행한다. 인자가 없으면 현재 시각을 난수 시드로 사용한다. 정수 인자를 주면 같은 실행 환경에서 그래프를 재현할 수 있다. 다른 C 라이브러리에서는 `rand()` 구현 차이로 결과가 달라질 수 있다.

## 그래프 생성

정점의 번호는 0에서 9고 인접 행렬의 0은 간선이 없다는 뜻이다. 존재하는 간선에는 1에서 100의 정수 가중치를 부여하고 양쪽 행렬 칸에 같은 값을 저장한다.

먼저 정점 순서를 무작위로 섞고 각 정점을 그보다 앞서 연결된 정점 하나와 연결하여 9개의 간선으로 모든 정점을 연결한다. 그 후 존재하지 않는 `u < v` 간선 후보 중 11개를 무작위로 선택하여 총 20개를 만든다. 이 방법으로 자기 간선과 중복을 방지하고 연결성을 보장한다. 연결 그래프 전체에서 균등하게 표본을 뽑는 방법은 아니지만 무작위 연결 그래프라는 조건을 충족한다.

생성 후 정점별 행렬의 대칭성, 가중치 범위, 간선 수 20개, 대각선 0을 검사하고 BFS로 정점 10개 모두에 도달하는지 확인한다. 최단거리 계산에 앞서 생성된 간선 20개와 가중치를 출력한다.

## Floyd–Warshall과 경로 복원

`distance[i][j]`에는 현재까지 알려진 최단거리, `next[i][j]`에는 i에서 j로 향하는 경로의 바로 다음 정점을 저장한다. 자기 자신까지의 거리는 0, 직접 연결된 경우 간선 가중치, 나머지는 INF로 초기화한다.

중간 정점 k를 0~9까지 추가하며 다음 조건을 검사한다.

```text
distance[i][k] + distance[k][j] < distance[i][j]
```

더 짧으면 거리를 갱신하고 `next[i][j] = next[i][k]`로 설정한다. 동일 비용이면 기존 경로를 유지하므로 여러 최단경로 중 하나만 출력한다. 도달 불가능한 구간은 합산하지 않는다. 양의 가중치에서 최단경로는 사이클을 포함할 필요 없고 최대 9개 간선의 합은 900이므로 INF=1,000,000은 충분히 큰 값이다.

경로 복원은 출발점부터 `next[현재 정점][도착점]`을 따라가며 정점을 모은다. 결과는 `u < v`인 경우에만 출력하므로 총 `10 × 9 / 2 = 45`쌍이며 역방향 중복이나 자기 자신 쌍을 출력하지 않는다. Floyd–Warshall의 시간 복잡도는 O(V³), 거리·경로 배열의 공간 복잡도는 O(V²)이다.

## 실제 실행 예

visual studio에서 실행하였다. 모든 간선과 45쌍의 경로·거리는 [result.txt](result.txt)에 저장하였다.

```text
0 -> 5
Path     : 0 -> 3 -> 2 -> 5
Distance : 53
```

이 그래프에는 직접 간선 `(0,5)`가 있지만 가중치는 62이다. 출력 경로는 `(0,3)=6`, `(3,2)=41`, `(2,5)=6`을 이용하여 `6+41+6=53`이 된다. 간선 세 개를 거치더라도 직접 간선 하나보다 비용이 작으므로 이 경로를 선택한다. 이는 간선 개수가 아니라 가중치 합을 최소화한 결과이다.

## 검증

프로그램과 테스트를 경고 없이 컴파일하였다.

제출 프로그램은 Floyd–Warshall 계산 후 각 정점에서 Dijkstra를 별도로 수행하여 모든 거리를 대조한다. 복원한 경로의 출발과 도착 정점, 중복 정점 없음, 실제 간선 존재 여부 및 가중치 합이 최단거리와 일치하는지도 확인한다. 검증 실패 시 오류로 종료한다.

별도 테스트에서는 시드 0~99의 무작위 그래프 100개에 대해 그래프 조건과 모든 경로를 검사하였다. 직접 간선 비용이 100이지만 9개 간선의 합이 9인 사례, 비용이 같은 경로가 여러 개인 사례, 비연결 그래프와 변조된 거리의 거부도 확인하였다. 비연결 그래프 검사는 보조 함수 검증용이고 제출 프로그램이 생성하는 그래프는 항상 연결 그래프이다.

저장된 출력 파일도 따로 읽어 간선이 20개인지, `u < v`의 중복 없는 쌍이 45개인지, 출력된 모든 경로의 간선 가중치 합이 출력 거리와 일치하는지 확인하였다.
