# 과제 06: 순차 탐색, BST와 AVL 트리 비교

## 데이터 처리

과제 5와 달리 서로 다른 값 100개가 모일 때까지 반복하지 않는다. 0~1000의 값을 정확히 100번 생성하고 중복도 생성 목록에 포함한다. 중복이면 저장하지 않으므로 실제 저장 수는 100보다 작을 수 있다. 난수 범위를 균등하게 매핑하기 위한 `rand()`의 나머지 구간 제외는 저장값 중복에 대한 재생성이 아니다.

매번 동일한 값을 배열, BST, AVL에 전달한다. 배열은 현재 길이만큼 순차 탐색한 후 없는 값만 끝에 붙인다. BST와 AVL은 배열의 중복 검사 결과를 이용하여 삽입을 생략하지 않으며 각자의 루트부터 독립적으로 삽입 위치 또는 중복을 찾는다. 중복을 확인한 비용도 세 자료구조 각각의 생성 비용에 포함된다. 배열은 최초 발생 순서를 유지하며 정렬하지 않는다.

BST와 AVL은 데이터, 높이, 좌우 자식 포인터를 가진 연결 노드를 사용한다. BST는 높이만 갱신하고 회전하지 않는다. AVL은 삽입 후 균형 인수가 +1보다 크거나 -1보다 작으면 LL·RR·LR·RL 회전으로 복구한다. 두 트리는 동일한 삽입 함수에서 균형 복구 여부만 달리하므로 데이터 비교 기준이 같다.

저장이 끝난 후 탐색 키 50개를 추가로 생성하여 세 방식에서 모두 검색한다. 탐색 키끼리의 중복은 허용한다.

## 비교 횟수와 높이 기준

- 배열: 저장값과 새 값 또는 탐색 키의 `==` 실행마다 1회이다.
- BST·AVL: 저장값과의 `==` 실행마다 1회이며, 불일치하여 `<`로 방향을 정하면 추가 1회이다. 이 규칙을 생성과 탐색에 모두 적용한다.
- 중복을 발견한 마지막 노드는 동등 비교 1회만 센다. 첫 루트 삽입은 기존 데이터와 비교하지 않아 0회이다.
- 높이 계산, 균형 인수, 회전 판단, 포인터와 반복문 조건, 난수 생성, 통계 검증은 데이터 비교에 포함하지 않는다. AVL 회전 방향은 새 데이터와 재비교하지 않고 자식의 균형 인수로 판단한다.

따라서 본 보고서의 비교 횟수는 단순 방문 노드 수와 다르다. 높이 h의 트리에서 성공 탐색은 최대 `2h - 1`, 실패 탐색은 최대 `2h`회의 비교가 발생한다.

높이는 경로에 포함되는 노드 수로 정의하였다. 빈 트리는 0, 루트만 있으면 1이다. 높이 갱신식은 `1 + max(왼쪽 높이, 오른쪽 높이)`이다.

## 실행 결과

visual studio에서 `20261007`로 실행하였다. 전체 생성값, 실제 저장 배열, 탐색 키와 50개의 개별 결과는 [result.txt](result.txt)에 기록하였다.

100번 생성하여 서로 다른 값 97개가 저장되었고 중복 발생 3번은 삽입하지 않았다. 중복으로 제외된 값은 65, 848, 121이다. 배열 길이는 97이고 BST와 AVL에도 동일한 97개 값이 저장되었다. 탐색 50회 중 5회 성공하고 45회 실패하였다.

| 항목 | 배열 / 순차 탐색 | BST | AVL |
|---|---:|---:|---:|
| 생성 비교 횟수 | 4,771 | 1,295 | 1,085 |
| 배열 길이 또는 트리 높이 | 길이 97 | 높이 15 | 높이 8 |
| 탐색 총 비교 횟수 | 4,593 | 825 | 655 |
| 탐색 평균 비교 횟수 | 91.86 | 16.50 | 13.10 |
| 생성 + 탐색 비교 횟수 | 9,364 | 2,120 | 1,740 |

### 생성 비용 분석

배열은 새로운 값을 추가할 때 기존 원소 전체를 확인해야 한다. 서로 다른 97개가 들어가는 과정만으로 `0 + 1 + ... + 96 = 4656`회의 비교가 필요하다. 중복 발생 3번의 검사 비용 115회를 더하면 실측값 4,771회가 된다. 중복이 발생하면 재생성하지 않지만 중복 확인 비용은 없어지지 않는다.

BST는 루트부터 삽입할 경로만 따라가므로 1,295회, AVL은 균형을 유지한 경로로 삽입하여 1,085회였다. 이번 실험에서 AVL의 생성 데이터 비교는 BST보다 210회 적었다. 이는 회전을 무료로 실행했다는 의미가 아니라 과제의 측정 기준에서 회전과 높이 계산 비용을 제외한 결과이다.

### 높이와 탐색 비용 분석

동일한 97개 값을 같은 순서로 넣었지만 BST 높이는 15, AVL 높이는 8이었다. 일반 BST는 생성 순서에 따라 긴 가지가 그대로 남는 반면 AVL은 높이 차이가 커진 부분에서 회전하여 일부 노드의 위치를 바꾸기 때문이다. 저장된 값의 집합은 같고 연결 구조만 달라진다.

순차 탐색은 실패 45회에서 `45 × 97 = 4365`회를 비교하였다. 성공한 5회의 비교 합은 228회이며 두 값을 합하면 4,593회이다. 전체 1001개 값 중 저장값은 97개뿐이므로 무작위 탐색의 성공 확률은 약 9.69%이다. 이번 실험에서 실패가 많았던 이유이며 평균 순차 탐색 비교가 배열 길이 97에 가까운 91.86회가 된 원인이다.

BST는 평균 16.50회, AVL은 13.10회로, AVL이 50회 합계에서 170회 적게 비교하였다. 이번 AVL은 높이가 8이므로 실패 탐색도 최대 16회 비교하면 끝나는 반면 높이가 15인 BST는 최대 30회까지 가능하다. 높이가 낮으면 긴 탐색 경로가 제한되며 이번 키들에 대한 평균 비교도 줄어들었다. 두 높이의 비율만큼 평균 비용이 줄어들지는 않는다. 실제 비용은 각각의 키가 지나가는 경로와 성공 위치에 따라 달라진다.

### 생성 비용까지 포함한 분석

생성과 탐색의 합은 배열 9,364회, BST 2,120회, AVL 1,740회이다. 이번 데이터에서는 탐색뿐 아니라 중복 확인을 포함한 생성 과정에서도 트리 방식이 적은 비교를 수행하였다. AVL은 BST보다 합계 380회 적었다. 따라서 이번 실험의 데이터 비교 횟수 기준에서는 AVL, BST, 배열 순으로 유리하였다.

이는 모든 난수 실험에서 AVL의 개별 탐색이나 총비용이 항상 가장 작다는 뜻은 아니다. 일반 BST가 우연히 균형에 가까운 구조를 만들거나 특정 키가 루트 근처에 몰리면 차이가 줄거나 개별 탐색 결과가 반대일 수도 있다.

## 검증 결과

프로그램과 검증 파일을 컴파일하여 경고 없이 통과하였다. 별도 검증 파일은 다음을 확인한다.

- LL·RR·LR·RL 각각의 회전 후 루트와 좌우 자식, 높이
- 중복 재삽입이 노드를 추가하지 않으며 비교 비용은 증가하는지
- 시드 5개에서 총 500번 삽입 후 매번 BST 정렬 조건, 노드 수, 저장된 높이, AVL 균형 조건
- 삽입 비교 비용이 삽입 전 해당 키를 검색하는 비교 비용과 같은지
- 시드별 0~1000 전체 키에 대한 총 5,005회 검사에서 세 자료구조의 성공 여부가 실제 저장 집합과 같은지

별도로 오름차순 100개를 넣으면 BST는 높이 100과 생성 비교 9,900회, AVL은 높이 7과 생성 비교 1,146회가 나왔다. BST에서는 기존 노드마다 `==`, `<` 두 번을 실행하므로 `2 × (0 + ... + 99) = 9900`이다. 이 사례는 AVL이 불리한 삽입 순서에서도 긴 일자형 트리를 방지한다는 점을 보여 준다. 검증용 정렬 입력은 본 실험과 별개이며, 제출 프로그램의 배열을 정렬한 것이 아니다.

실제 출력 파일에서도 생성값 100개, 고유값 97개, 탐색 결과 50행을 확인하고 세 비교 횟수를 다시 합산하여 총계와 일치하는지 검사하였다.

## 해석 시 유의점

이 실험의 성능 지표는 데이터 비교 횟수이다. AVL의 높이 갱신과 회전, 메모리 할당 비용은 제외하므로 비교 횟수가 작다는 사실만으로 실제 실행 시간도 같은 비율로 짧다고 단정할 수 없다.

일반 BST는 삽입 순서에 따라 모양이 정해진다. 무작위 데이터에서도 일부 가지가 길어질 수 있으며 정렬된 값을 넣으면 일자형이 되어 높이가 n까지 커진다. AVL은 각 노드의 좌우 높이 차이를 1 이하로 유지하여 높이가 O(log n)이 되도록 한다. 높이는 가장 긴 경로의 길이이므로 높이가 낮다고 모든 개별 키를 반드시 더 적은 비교로 찾는 것은 아니다.

배열의 순차 탐색은 실패하면 저장된 원소를 전부 비교한다. BST와 AVL은 값의 대소 관계에 따라 한쪽 서브트리를 제외하므로 전체 데이터를 확인하지 않아도 실패를 판정한다. 탐색을 반복할수록 탐색당 비용의 차이가 누적되며 생성 비용까지 합한 결과와 함께 판단해야 한다.
