# 과제 13: 병합 정렬과 퀵 정렬의 성능 비교

## 실행 및 입력 조건

`hw13.c`을 컴파일한다. 기본 시드는 과제 12에서 사용한 `20261104`이며 인자로 다른 시드를 줄 수 있다. 크기별 `srand(seed+n)`과 난수 생성 방식을 유지하여 동일 환경의 과제 12와 같은 입력을 재현한다. 값 범위는 0~1,000,000이고 중복을 허용한다. C 라이브러리의 `rand()` 구현이 다르면 동일 시드라도 데이터가 달라질 수 있다.

크기는 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000이며 각 크기에서 네 알고리즘에 같은 원본의 복사본을 제공한다. 크기마다 무작위 원본 하나를 사용한다. 정렬 결과를 별도의 기준 정렬과 원소별로 대조해 오름차순과 중복을 포함한 값 보존을 검사한다. `qsort`는 기준 결과 생성용이며 실험 대상 정렬은 직접 구현했다.

## 알고리즘 및 측정 기준

병합 정렬은 구간을 절반으로 나누어 재귀적으로 정렬한 후 하나의 임시 배열을 재사용하여 병합한다. 양쪽 원소가 남아 있을 때 `a[i] <= a[j]` 비교를 1회로 센다. 한쪽이 소진된 뒤 남은 값을 복사하는 과정에는 데이터 비교가 없다.

퀵 정렬은 과제 12의 첫 원소, 매 분할마다 무작위 위치, 첫·가운데·마지막 값의 중앙값을 사용하는 세 방식을 유지했다. 피벗을 마지막으로 옮기는 동일한 Lomuto 분할을 사용하고 `< pivot` 비교와 중앙값 선택에서 실행한 모든 값 비교를 센다. 인덱스 검사, 데이터 생성·복사·검증은 비교 횟수에서 제외한다.

Windows에서는 `QueryPerformanceCounter`로 ms를 측정한다. 다른 플랫폼에서는 `clock()`의 CPU 시간을 사용하므로 서로 다른 타이머 환경의 결과는 직접 비교하지 않는다. 원본 복사, 난수 시드 재설정, 결과 검증·출력과 임시 배열 할당은 타이머 밖이다. 병합 정렬의 실제 병합용 복사는 정렬 작업이므로 시간에 포함한다. 무작위 피벗의 난수 생성도 정렬에 필요한 작업으로 시간에 포함한다. 모든 방식에서 비교 계수 갱신 비용도 포함한다.

각 방식은 한 번 예열하고 같은 입력을 100회 정렬해 평균 시간을 출력한다. 실행 순서를 네 알고리즘 사이에서 순환시킨다. 무작위 피벗은 매회 같은 시드로 초기화하므로 같은 분할과 비교 횟수를 재현한다. 이는 100개의 새로운 입력에 대한 평균이 아니라 동일 정렬 작업의 시간 반복 측정이다. 매 실행의 비교 횟수가 최초 실행과 같은지 확인한다.

## 메모리 계산 기준

출력의 `Memory estimate(Bytes)`는 소스 수준 저장량 모델에 따른 최대 추가 메모리의 보수적 추정값이다. 프로세스 메모리나 컴파일된 코드의 실제 호출 스택을 프로파일링한 값은 아니다. 과제에서 허용한 직접 계산 방법을 사용한다.

시간 측정과 별도 실행에서 재귀 진입·반환을 세어 최대 동시 호출 깊이 D를 측정한다. 단일 원소 또는 빈 구간으로 종료하는 기저 호출도 포함한다. 프레임 구조체는 함수의 매개변수와 지역 변수에 해당하는 포인터·정수 저장량을 나타내며 `sizeof`로 구조체 패딩을 포함한다.

- 병합 정렬: `n*sizeof(int) + D*sizeof(MergeFrame)`. 임시 배열 n개를 한 번만 할당해 공유한다. 프레임 모델에는 배열·임시 배열·계수 포인터 3개와 lo, hi, mid, i, j, k 정수 6개가 있다.
- 퀵 정렬: `D*sizeof(QuickFrame) + helper`. 프레임은 배열·계수 포인터 2개와 lo, hi, method, p 정수 4개다. helper에는 분할 함수와 그 내부에서 피벗 선택·비교·교환·난수 함수가 사용하는 명시적 변수 공간의 가장 큰 호출 경로를 더한다. 세 피벗에 동일한 보수적 helper 기준을 적용한다.
- helper 계산: `sizeof(PartitionFrame) + max(sizeof(PivotFrame) + max(sizeof(RandomFrame), sizeof(LessFrame)), sizeof(SwapFrame))`.

최대 재귀 깊이에서 모든 보조 함수가 동시에 실행되는 것은 아니지만 이 계산은 깊이 D의 프레임에 보조 호출 공간을 더해 여유 있게 추정한다. 실제 ABI의 반환 주소, 레지스터 저장·전달, 스택 정렬 및 shadow space, 컴파일러 인라이닝·꼬리 호출 최적화, 라이브러리 내부 난수 상태·호출 스택, 메모리 할당기의 메타데이터는 이 모델에 포함하지 않는다. 따라서 실제 스택의 정확한 바이트나 엄밀한 상한이라는 의미는 아니다.

공통 입력·작업 배열, 기준 정렬 배열, 타이머·비교 계수·깊이 계측 상태는 실험용 공통 비용으로 제외한다. 병합 정렬의 임시 배열은 시간 측정 전에 할당해도 정렬에 필수이므로 메모리에 포함한다. 한 번에 한 정렬만 수행하는 것으로 계산하여 다른 알고리즘의 공간을 합산하지 않는다.

### 비교 횟수와 데이터 크기

병합 정렬의 비교 횟수는 n을 두 배로 늘리는 구간에서 약 2.17~2.22배로 증가했다. 퀵 정렬도 대체로 두 배 전후로 증가해 이번 무작위 입력에서는 네 방식 모두 O(n log n) 규모의 증가 경향을 보였다. 16,000→20,000은 1.25배 증가이므로 앞선 두 배 구간과 구별해야 한다.

모든 크기에서 병합 정렬의 비교가 가장 적었다. 20,000개에서는 병합 261,024회, 가장 적게 비교한 퀵 Median3도 317,880회여서 병합이 56,856회(약 17.89%) 적었다. 병합 정렬은 입력 값과 관계없이 구간을 거의 반으로 나누며 합칠 때 한쪽 구간이 소진되면 나머지는 값 비교 없이 복사한다. 퀵 정렬은 각 분할에서 피벗과 모든 나머지 원소를 비교하고 분할이 불균형하면 추가 단계가 필요하다.

### 실행시간 차이

비교가 적다고 반드시 빠르지는 않았다. 20,000개에서 First는 343,437회 비교했지만 0.765669ms로, 비교가 더 적은 병합의 0.780313ms보다 조금 짧았다. 병합 정렬은 임시 배열에 쓰고 원래 배열로 다시 복사하는 작업을 매 병합 단계마다 수행한다. 퀵 정렬은 같은 배열 안에서 교환한다. 이러한 메모리 읽기·쓰기, 분기, 함수 호출 및 캐시 동작도 시간에 영향을 주므로 비교 횟수만으로 시간을 예측할 수 없다.

Random은 20,000개에서 First보다 적게 비교했지만 실행시간은 1.071831ms로 더 길었다. 매 분할마다 난수 생성과 범위 제한 연산이 추가된다. 이번 구현의 난수 함수는 두 번의 `rand()`와 범위 처리를 사용하므로 이 비용도 시간에 포함된다. 이는 관찰된 차이를 설명하는 구현상의 요인이며 각 비용을 별도로 프로파일링한 결과는 아니다.

크기별로 1,000개에서는 Median3, 나머지에서는 First의 시간이 가장 짧았다. 그러나 20,000개의 병합과 Median3 차이는 약 0.003742ms에 불과했다. 반복 평균을 사용했어도 운영체제 스케줄링과 CPU 상태 등의 영향을 받으며 분산을 측정하지 않았으므로 작은 시간 차이를 보편적 우열로 해석하지 않는다.

### 메모리와 복잡도

병합 정렬의 추가 메모리 추정은 1,000개에서 4,528Byte, 20,000개에서 80,768Byte로 증가했다. 후자는 임시 배열 80,000Byte와 최대 깊이 16 × 프레임 48Byte의 합이다. 크기가 증가하면 임시 배열이 지배하므로 추가 공간은 O(n)이고 재귀 스택 부분은 O(log n)이다. 시간은 입력 상태에 관계없이 O(n log n)이다.

퀵 정렬에는 원소 수에 비례하는 임시 배열이 없다. 20,000개의 추가 공간 추정은 First 1,152Byte, Random 1,216Byte, Median3 864Byte였다. 각각 측정 깊이 33, 35, 24에 프레임 32Byte와 보조 공간 96Byte를 적용한 값이다. 병합보다 호출 깊이는 커도 큰 임시 배열이 없어서 이번 계산에서는 훨씬 적었다. 깊이만 보면 Median3이 Random보다 얕았지만 깊이는 가장 긴 경로이고 총 비교는 모든 분할의 합이므로 둘이 완전히 비례하는 것은 아니다.

퀵 정렬은 평균 O(n log n) 시간과 O(log n) 재귀 공간을 사용하지만 편향된 분할이 계속되면 시간 O(n²), 재귀 공간 O(n)까지 증가한다. 이 구현의 First는 정렬된 서로 다른 값에서 세 방식 모두 같은 값만 있는 경우에는 한쪽으로 치우친다. 큰 최악 입력에서는 재귀 스택 한계도 문제가 될 수 있다. 평균 성능과 적은 추가 공간을 중시하면 퀵 정렬이 유리할 수 있고 임시 배열을 허용하면서 최악 시간 O(n log n)을 보장하려면 병합 정렬이 적절하다.

### 피벗 선택의 영향

퀵 정렬만 비교하면 Median3은 6개 중 4개 크기에서 총 비교가 최소였고 4,000개와 16,000개에서는 First가 최소였다. 중앙값 선택은 극단적인 피벗을 피하는 데 도움이 되지만 매 분할의 2~3회 값 비교가 추가된다. 선택 비용이 분할 개선 효과를 초과하면 First보다 비교가 많아질 수 있다. Random도 항상 중앙에 가까운 값을 선택하는 것은 아니며 이번 입력에서는 처음 다섯 크기의 비교 횟수가 세 퀵 방식 중 가장 많았다.

이전 과제와 같은 입력·피벗 난수열에서 퀵 정렬의 비교 횟수가 과제 12 결과와 모두 일치했다. 이번 실험은 크기별 입력 하나이므로 다른 시드나 정렬·역순·중복이 많은 입력에서는 결과가 달라질 수 있다. 시간 반복 100회는 입력 다양성을 늘린 실험이 아니다.

## 검증

중복을 포함한 길이 5 입력 243개 × 네 알고리즘의 결과, 병합 정렬의 정확한 비교 횟수, 재귀 깊이, 빈 배열과 단일 원소를 검사한다.

실제 결과: 컴파일 성공. 972개 정렬 사례와 별도 검사 통과. 6개 크기 × 4가지 방식 및 각각 100회 반복의 결과·비교 횟수 검사도 모두 PASS였다.
