# 과제 05: 순차 탐색과 이진 탐색 트리 탐색 비교

## 실행 방법

Windows에서는 실행 파일 이름을 `hw5.exe`로 사용할 수 있다. 인자가 없으면 실행 시각을 난수 시드로 사용하고 정수 인자를 주면 해당 값을 시드로 사용한다. 같은 실행 환경에서 같은 시드를 사용하면 결과를 재현할 수 있다. C의 `rand()` 구현은 환경에 따라 다르므로 다른 컴파일 환경에서는 같은 시드여도 값이 달라질 수 있다.

0부터 1000까지의 정수를 생성하고 이미 나온 값은 버린 뒤 다시 생성하여 서로 다른 100개를 얻는다. 배열은 생성 순서를 유지하며 정렬하지 않는다. 같은 배열을 앞에서부터 읽어 포인터 기반 BST에 삽입한다. 그 후 탐색 대상 50개를 추가로 생성하여 두 방법에 동일하게 사용한다. 탐색 대상끼리의 중복은 허용한다.

`random_value`는 `rand()`의 범위를 1001(0~1000)로 나눌 때 남는 구간을 제외하여 단순 나머지 연산에 의한 편향을 피한다. 이것은 저장 데이터의 중복 제거와는 별도 처리이다.

## 비교 횟수의 기준

탐색 키 또는 삽입할 값과 저장된 정수 사이에 실제 실행한 비교 연산 수를 센다. (방문한 노드 수 x)

| 처리 | 비교 횟수 |
|---|---|
| 순차 탐색 | 배열 원소와 `==`를 실행할 때마다 1회 |
| BST 탐색 | 현재 노드와 `==`를 실행할 때 1회, 불일치하여 방향을 정하는 `<`를 실행하면 추가 1회 |
| BST 삽입 | 기존 노드와 `<`를 실행할 때마다 1회 |

중복 없는 데이터만 삽입하므로 삽입 과정에서는 별도의 동등 비교가 필요 없다. 첫 루트 생성에는 비교가 없으며 생성 비용은 0회다. BST 탐색은 성공한 마지막 노드에서 1회, 지나친 노드에서는 2회를 센다. 이 때문에 BST 비교 횟수는 단순 방문 노드 수와 다를 수 있다.

루프 인덱스·포인터·통계 계산의 비교, 데이터 생성과 중복 확인, 메모리 할당과 입출력은 측정 대상에 포함하지 않는다. 생성과 중복 제거는 두 방식이 공유하는 준비 작업이다. 배열은 준비된 데이터를 그대로 저장하므로 추가적인 저장 위치 결정 비교가 없지만 BST의 삽입 비교는 별도로 측정하여 합산한다. 따라서 이 실험은 전체 실행 시간이 아니라 명시한 데이터 비교 비용을 비교한다.

## 실제 실행 결과와 분석

전체 100개 데이터, 50개 탐색 키, 각 키의 결과와 비교 횟수는 [result.txt](result.txt)에 저장하였다.

| 항목 | 실측값 |
|---|---:|
| 저장 데이터 수 | 100개, 중복 없음 |
| 탐색 횟수 | 50회 |
| 성공 / 실패 | 5회 / 45회 |
| BST 높이 (루트 깊이 0) | 9 |
| 순차 탐색 총 비교 횟수 | 4,856회 |
| 순차 탐색 평균 비교 횟수 | 97.12회 |
| BST 탐색 총 비교 횟수 | 711회 |
| BST 탐색 평균 비교 횟수 | 14.22회 |
| BST 생성 비교 횟수 | 558회 |
| BST 생성 + 50회 탐색 | 1,269회 |

### 탐색 비용만 비교

순차 탐색은 실패한 45회에서 매번 100개를 모두 비교하므로 실패 탐색만으로 4,500회의 비교가 발생하였다. 성공한 5회의 평균도 71.20회로 찾는 값들이 배열의 비교적 뒤쪽에 있었다. 총 비교는 `4500 + 5 × 71.20 = 4856`회이며 전체 평균은 97.12회로 높게 나타났다.

저장 값은 전체 1001개 중 100개이므로 독립적으로 생성한 키가 성공할 확률은 약 `100 / 1001`, 약 10%이다. 이번 실험에서 성공이 5회고 실패가 45회인 결과는 이 데이터 구성과도 잘 맞는다. 탐색 성공을 강제로 보장하거나 실패 키를 따로 선정하지 않았다.

BST는 성공 시 평균 13.00회, 실패 시 평균 약 14.36회 비교하였다. 높이가 9기에 긴 경로도 최대 10개 노드만 확인하면 되고 매 단계에서 한쪽 서브트리를 제외할 수 있기 때문이다. 각 노드에서 최대 두 번 비교하도록 세었는데도 탐색 총비용은 711회로 순차 탐색보다 4,145회 적었다.

### 생성 비용을 포함한 비교

BST 생성에는 558회의 비교가 추가로 필요했다. 따라서 전체 비용은 `558 + 711 = 1269`회다. 배열은 생성 순서대로 저장할 때 데이터 간 비교가 필요 없으므로 전체 비교 비용은 순차 탐색의 4,856회이다. 생성 비용까지 포함해도 이번 실험에서 BST는 3,587회로 약 73.87% 적게 비교하였다.

생성 비용은 탐색 전에 한 번 발생한다. 이번 평균 탐색 비용이 유지된다고 가정하면 탐색 q회의 비용은 순차 탐색 약 `97.12q`로 BST 약 `558 + 14.22q`이다. 두 식을 비교하면 `q > 558 / (97.12 - 14.22) ≈ 6.73`이므로 약 7회부터 생성 비용을 상쇄할 것으로 추정된다. 이는 이번 50회에서 얻은 평균에 근거한 추정이며 실제 앞의 7회나 다른 탐색 데이터에서 항상 성립한다는 뜻은 아니다.

### 다른 시드의 추가 실행

한 번의 결과만으로 일반화하지 않기 위해 같은 환경에서 시드를 바꿔 추가 실행하였다.

| 시드 | 성공 / 실패 | 순차 총 / 평균 | BST 탐색 총 / 평균 | BST 생성 | BST 생성 + 탐색 |
|---|---|---|---|---:|---:|
| 1 | 6 / 44 | 4,657 / 93.14 | 852 / 17.04 | 714 | 1,566 |
| 42 | 4 / 46 | 4,809 / 96.18 | 824 / 16.48 | 628 | 1,452 |
| 20261002 | 5 / 45 | 4,856 / 97.12 | 711 / 14.22 | 558 | 1,269 |

세 실험에서는 모두 생성 비용을 포함한 BST 비교 횟수가 더 작았다. 그러나 생성 순서와 탐색 키가 바뀌면서 생성·탐색 비용도 달라졌다. 이는 일반 BST의 성능이 데이터 개수뿐 아니라 삽입 순서와 만들어진 구조에도 영향을 받음을 보여 준다.

## 트리 구조가 성능에 미치는 영향

BST는 현재 값과의 대소 관계로 한쪽 서브트리를 제외하므로 트리가 균형에 가까우면 적은 노드만 방문한다. 높이가 O(log n)이면 탐색 비용도 O(log n)에 해당한다. 순차 탐색은 입력 순서대로 값을 확인하며 실패할 때는 항상 n개 모두와 비교한다.

일반 BST는 스스로 균형을 맞추지 않는다. 무작위 삽입은 좋은 평균 성능을 기대할 수 있지만 균형을 보장하지 않는다. 정렬된 100개 값을 오름차순으로 삽입하면 높이가 99인 오른쪽 편향 트리가 된다. 이때 생성 비용은 `0 + 1 + ... + 99 = 4950`회이다. 가장 깊은 노드를 찾으면 `2 × 99 + 1 = 199`회, 모든 값보다 큰 없는 키를 찾으면 `2 × 100 = 200`회 비교한다. 이 구현의 순차 탐색은 최대 100회이므로 편향된 BST가 오히려 불리할 수 있다.

동일한 BST를 여러 번 검색하면 생성 비용을 여러 탐색에 나누어 부담하게 된다. 탐색을 아주 적게 수행하거나 트리가 심하게 편향되면 생성 비용을 회수하지 못할 수 있다. 따라서 탐색 횟수, 성공·실패 비율, 배열 내 위치, BST의 높이와 모양을 함께 고려해야 한다.

## 검증

`visual studio`로 경고 없이 컴파일하였다. 시드 3개에서 저장값의 범위와 중복 없음을 확인하고 각 시드에서 0~1000의 모든 키를 조회하는 총 3,003회 검사를 수행하였다. 두 탐색의 성공 여부를 실제 배열의 포함 여부와 대조하였다.

순차 탐색 성공 시 비교 횟수가 배열 위치 + 1인지, 실패 시 100인지 확인하였다. 별도의 작은 트리에서는 BST 생성 6회, 루트 검색 1회, 깊이 2의 성공 검색 5회, 3개 노드를 거친 실패 검색 6회를 확인하였다. 생성 비교 횟수는 모든 노드의 최종 깊이 합과 일치하는지도 검사하였다.

오름차순 100개를 삽입하는 별도 검증에서는 생성 4,950회, 높이 99, 마지막 노드 검색 199회와 큰 값의 실패 검색 200회를 확인하였다. 제출용 실행 결과 50행의 비교 횟수를 별도로 합산하여 출력된 총계와도 대조하였다. 이 검증용 정렬 데이터는 본 실험의 무작위 배열과 별개이며 제출 프로그램은 배열을 정렬하지 않는다.
