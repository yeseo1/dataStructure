# 과제 03: 트리 조작 프로그램

## 실행과 명령 입력

`hw3.c`를 독립적인 C 프로그램으로 컴파일하여 실행한다. 이전 과제 파일에도 `main`이 있으므로 하나의 실행 파일에 함께 넣지 않는다. 프로그램은 최대 100개의 노드를 저장하는 빈 이진트리로 시작한다. 최대 노드 수는 `MAX_NODES`로 지정하고 `create_btree(MAX_NODES)`에 전달한다.

명령은 한 줄에 하나씩 입력한다. 명령어는 표에 적힌 전체 이름 또는 대문자 약어를 사용한다. 데이터는 영문 대문자 한 글자이고 같은 문자를 서로 다른 위치에서 사용할 수 있다.

| 명령 | 기능 |
|---|---|
| `Insert / A` 또는 `I / A` | 빈 트리에 루트 A 생성 |
| `Insert /A L B` 또는 `I /A L B` | A의 비어 있는 왼쪽 자식 위치에 B 추가 |
| `Insert /A Right B` | A의 비어 있는 오른쪽 자식 위치에 B 추가 |
| `Delete /A/B` 또는 `D /A/B` | 단말 B 삭제 |
| `Update /A/B X` 또는 `U /A/B X` | B의 데이터를 X로 변경 |
| `Read /A` 또는 `R /A` | A의 자식 데이터와 L/R 위치 출력 |
| `Print` 또는 `P` | 전체 트리 출력 |
| `Quit` 또는 `Q` | 모든 노드와 트리 관리 구조체를 해제하고 종료 |

자식 위치는 `L`, `Left`, `R`, `Right`를 지원한다. 종료 명령은 반복 메뉴를 끝내기 위해 추가하였고 입력이 끝나는 EOF에서도 메모리를 해제하고 종료한다. 명령 사이에는 공백이나 탭을 사용할 수 있지만 `/A/B`와 같은 경로 내부에는 공백을 넣지 않는다.

## ADT 구현

연결 자료구조를 사용하였다. `Node`는 문자 데이터와 왼쪽·오른쪽 자식 포인터를 저장한다. `BinaryTree`는 루트 포인터, 최대 노드 수 `size`, 현재 노드 수 `count`를 관리한다. 빈 트리는 루트 포인터가 `NULL`인 상태이다.

| 연산 | 구현 내용 |
|---|---|
| `create_btree(size)` | 양수인 최대 용량을 받아 빈 트리를 생성한다. 잘못된 용량이나 할당 실패 시 NULL을 반환한다. |
| `insert_root(tree, value)` | 빈 트리에만 루트를 추가하고 트리를 반환한다. |
| `insert_child(tree, parent, child, value)` | 부모 경로, 위치, 데이터, 해당 위치의 빈 상태, 형제 중복과 용량을 확인한 후 추가한다. |
| `delete_node(tree, leaf)` | 경로의 노드가 단말이면 연결을 끊고 해제한다. 루트도 단말이면 삭제할 수 있다. |
| `update_value(tree, node, value)` | 경로의 노드를 찾아 형제와 중복되지 않는 대문자로 수정한다. |
| `read_child(tree, parent)` | `ChildInfo` 구조체를 반환한다. `found`는 경로 존재 여부이며, `left`와 `right`는 자식 데이터이다. 없는 자식의 값은 널 문자이다. |
| `print_btree(tree)` | 루트, 왼쪽, 오른쪽 순서로 들여쓰기와 `+---`를 출력한다. |
| `destroy_btree(tree)` | 자식부터 재귀적으로 해제한 뒤 트리 관리 구조체까지 해제한다. |

변경 연산은 전달받은 트리를 수정하고 같은 트리 포인터를 반환한다. 실패하면 오류 메시지를 출력하고 변경하지 않은 트리를 반환한다. `parent`, `leaf`, `node`는 메뉴에서 입력한 경로 문자열로 전달한다.

### 경로 탐색과 데이터 수정

`find_link`는 경로가 `/대문자/대문자/...` 형식인지 먼저 검사한다. 첫 데이터가 루트와 일치하는지 확인한 뒤 각 단계에서 현재 노드의 왼쪽 또는 오른쪽 자식 중 다음 데이터와 일치하는 노드로 이동한다. 전체 트리에서 문자 하나를 검색하는 방식이 아니므로 서로 다른 위치의 같은 데이터를 구분할 수 있다.

탐색 결과는 노드를 가리키는 포인터의 주소로 반환한다. 일반 노드는 부모의 자식 포인터를 루트는 트리의 루트 포인터를 동일한 방식으로 갱신하여 삭제할 수 있다.

경로를 별도로 저장하지 않기 때문에 노드 데이터를 바꾸면 이후 탐색에 곧바로 반영된다. 예를 들어 `/A/B/C`를 X로 수정하면 자신은 `/A/B/X`가 되고, 자식 D가 있으면 그 경로도 `/A/B/X/D`가 된다. 이전 경로로 요청하면 오류가 발생한다.

### 자식 추가 조건

수정된 삽입 조건인 “자식이 2개 미만인 노드 아래에 추가”를 적용하였다. 부모가 단말 노드가 아니어도 지정한 자식 위치가 비어 있으면 추가할 수 있다. 예를 들어 `Insert /A L B` 다음에 `Insert /A R C`를 수행하면 A의 두 자식 B와 C가 만들어진다.

자식이 하나뿐이어도 이미 사용 중인 위치를 지정하면 오류를 출력한다. 기존 자식이나 서브트리를 덮어쓰지 않는다. 삭제는 단말 노드에만 허용한다.

## 오류 처리

다음 입력은 오류 메시지를 출력한 뒤 다음 명령을 계속 받는다.

- 없는 경로 또는 `/A//B`, `/A/B/`처럼 문법이 잘못된 경로
- 알 수 없는 명령, 빈 명령, 인자가 부족하거나 너무 많은 명령
- 대문자 한 글자가 아닌 데이터 또는 잘못된 자식 위치
- 비어 있지 않은 트리에 루트 추가
- 이미 사용 중인 자식 위치에 추가 또는 비단말 노드 삭제
- 같은 부모 아래에서 자식 데이터가 중복되는 추가·수정
- 최대 노드 수를 초과하는 추가 또는 메모리 할당 실패
- 입력 버퍼에 담을 수 없을 만큼 긴 명령

검사와 메모리 할당이 성공한 뒤에만 트리의 포인터, 데이터, 노드 수를 변경한다. 너무 긴 명령은 남은 부분을 줄 끝까지 버려 다음 명령으로 잘못 처리하지 않는다. 삭제하면 현재 노드 수가 감소하므로 다시 추가할 수 있다.

## 실행 예

다음 명령을 한 줄씩 입력한다.

```text
Insert / A
Insert /A L B
Insert /A/B L C
Insert /A/B/C R D
Print
Read /A/B/C
Update /A/B/C X
Delete /A/B/X/D
Print
Quit
```

첫 번째 `Print`의 결과는 다음과 같다.

```text
A
+---B
    +---C
        +---D
```

`Read /A/B/C`는 `D(R)`을 출력한다. C를 X로 수정하고 새로운 경로로 D를 삭제한 뒤의 출력은 다음과 같다.

```text
A
+---B
    +---X
```

## 검증 결과

Windows x64에서 visual studio 2026을 통해 경고와 오류 없이 컴파일되었으며 다음 검사를 통과하였다.

- 과제에 제시된 삽입·조회·수정·삭제 실행 예
- 잘못된 명령 26종에 대한 오류 출력, 트리 상태 유지 및 다음 명령 처리
- 서로 다른 깊이의 중복 데이터, 루트와 단말 수정, 수정 전 경로 거부
- 루트 삭제 후 빈 트리 출력과 루트 재생성
- 100개 용량 제한 및 삭제 후 공간 재사용
- 전체 명령 이름, 약어, `Left`·`Right`, EOF 종료

이미 사용 중인 위치의 추가, 두 자식이 모두 있는 부모에 추가, 형제 중복 추가·수정이 오류로 처리되고 트리를 유지하는지도 검증하였다. `/A/B/D`와 `/A/C/D`의 중복 데이터 D는 각각 다른 경로로 조회·수정·삭제할 수 있다.
