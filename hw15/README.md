# 과제 15: 퀵 정렬과 AVL 트리 정렬의 성능 비교

## 실행 방법

`hw15.c`를 컴파일한다. 기본 시드는 20261104이며 인자로 다른 시드를 줄 수 있다. 데이터 생성 방식과 크기별 시드 `seed+n`을 유지하여 같은 난수 라이브러리 환경에서는 이전 과제의 입력을 재현한다. C 라이브러리가 달라지면 같은 시드라도 결과가 달라질 수 있다.

## 입력 및 자료구조

크기는 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000이다. 각 크기에서 0~1,000,000 정수 n개를 생성하며 중복을 허용한다. 이어서 n/5개의 연산 목록을 미리 생성한다. 각 연산에서는 난수를 한 번 생성해 짝수이면 삽입, 홀수이면 삭제를 선택하고, 별도의 새 난수로 대상 값을 정한다. 두 방식에 같은 입력과 연산 목록을 적용한다. 삽입과 삭제를 각각 20% 수행하는 것이 아니라 합계 20%다.

- 배열: 이전 과제의 Median-of-Three 피벗 + Lomuto 분할 퀵 정렬을 사용한다. 삽입은 처음부터 `a[pos] < value`로 선형 탐색해 첫 번째 같거나 큰 값 앞에 넣고 뒤쪽을 이동한다. 삭제는 처음부터 `a[pos] == value`로 탐색해 최초 일치 원소 하나만 지운다. 실패하면 변경하지 않는다. 삭제는 끝까지 탐색하는 구현이며, 정렬 상태를 이용한 조기 종료나 이진 탐색을 적용하지 않았다.
- AVL: 서로 다른 키마다 노드 하나를 만들고 중복은 count에 누적한다. 삽입·삭제 뒤 높이를 갱신하고 필요한 LL/RR/LR/RL 회전을 적용한다. 삭제 시 count가 2 이상이면 1만 감소한다. 자식이 둘인 노드를 지울 때는 후속 노드의 키와 중복 개수를 옮기고 후속 노드 전체를 제거하여 원래 대상 값 한 개만 줄인다.
- AVL은 배열로 변환해서 수정하지 않는다. 모든 변경은 트리 안에서 수행한다. 중위 순회는 각 키를 count번 방문해 오름차순 구성을 확인한다.

## 성능 지표의 기준

### 시간과 비교

Windows x64에서 QueryPerformanceCounter를 사용하고 단위는 ms다. 비 Windows의 대체 타이머는 clock의 CPU 시간이다. 정렬 시작부터 마지막 연산 완료까지를 한 번에 측정한다. 난수 생성, 연산 목록 준비, 초기 배열 복사, 결과 검증·출력 및 최종 자료구조 해제는 제외한다. AVL 노드 생성·삭제 중 malloc/free, 회전, 배열의 밀기 작업은 포함한다. 배열은 n+n/5 용량을 미리 할당하고 모든 삽입이 가능하도록 하여 재할당은 필요 없다. 이 용량은 메모리에 포함한다.

동일 입력과 동일 연산을 각 방식에서 10회 반복하고 총 시간의 평균을 출력한다. 매번 트리와 배열을 초기 상태로 되돌리며 실행 순서를 번갈아 적용한다. 이는 10개의 독립 난수 실험이 아닌 같은 작업의 시간 반복 측정이다. 비교와 이동은 한 번의 전체 작업에 대한 횟수이며 각 반복에서 같은지 확인한다.

실제 수행된 데이터 키 비교만 센다. 퀵 분할과 중앙값 선택을 포함한다. AVL은 각 방문에서 `==`를 한 번, 불일치 시 `<`를 한 번 실행하므로 불일치 노드에서는 **2회**다. 단순 방문 노드 수를 비교 횟수로 간주하지 않는다. 인덱스, 포인터 NULL, count, 높이 및 균형 인수 검사는 제외한다. 삭제 실패를 확인한 키 비교도 포함한다.

### 데이터 이동

알고리즘이 저장된 키 값 자체를 변수나 저장소로 복사·대입할 때 1회 센다.

- 퀵 교환은 임시 저장을 포함해 3회. 같은 위치끼리 교환하는 경우에도 실제 실행한 3회 대입을 센다. 피벗 값을 지역 변수에 저장하는 대입도 1회다.
- 배열 삽입의 각 밀기 및 새 값 저장, 삭제 후 각 당기기를 센다. 삭제된 마지막 슬롯은 활성 길이 밖으로 제외하며 불필요하게 0으로 덮어쓰지 않는다.
- AVL 새 노드의 키 저장은 1회, 두 자식 삭제의 후속 키 대입은 1회다. count·height 갱신과 포인터 연결·회전은 데이터 값 이동에서 제외한다. 따라서 중복 삽입·삭제는 키 이동이 0일 수 있다.

함수 인자 전달 및 반환의 ABI 복사, 비교를 위한 값 읽기, 공통 실험 입력 복사, 중위 순회 검증 버퍼 쓰기는 이동 집계에서 제외한다. 이 기준은 두 방식에 동일하게 적용한다. AVL 이동이 적다는 것은 키 복사가 적다는 의미이며 포인터 조작이나 메모리 할당 비용이 없다는 뜻은 아니다.

### 메모리

이번 과제는 자료구조 자체도 포함한다. 이전 과제의 추가 메모리 수치와 직접 비교하면 안 된다. 배열은 실제 할당한 `(n+n/5)*sizeof(int)`와 정렬 또는 선형 연산의 활성 프레임을 포함한다. AVL은 현재 살아 있는 노드 수 × sizeof(Node)에 현재 활성 재귀·보조 프레임을 더한다. 할당·해제와 함수 진입·반환 시 합을 갱신하여 전체 과정에서 가장 큰 값을 저장한다. 각각의 최대값을 서로 다른 시점에서 구해 무조건 더하지 않는다.

출력은 소스 수준 프레임 모델에 따른 `Memory estimate`이다. 본 환경에서는 Node=32, QuickFrame=48, ArrayFrame=40, TreeFrame=32, BalanceFrame=40, MinFrame=24Byte다. 퀵은 깊이별 QuickFrame, 배열 연산은 ArrayFrame을 사용한다. AVL 삽입·삭제는 TreeFrame, 후속 노드 분리는 MinFrame, 균형 복구는 BalanceFrame을 중첩해 계산한다. 구조체 sizeof로 포인터·정수·패딩을 반영한다.

이는 실제 ABI 호출 스택을 프로파일링한 값이 아닌 저장 공간 모델의 추정이다. 프레임 모델은 주요 인자·지역 변수와 보조 작업을 묶어서 표현하며 모든 임시 함수 호출을 별도 실측하지 않는다. 컴파일러의 레지스터·인라이닝·반환 주소·스택 정렬, 할당기 메타데이터, 라이브러리 내부 공간은 제외한다. 입력 원본, 공통 연산 목록, 검증 버퍼 및 계측기 상태도 제외한다. 배열의 미사용 예약 용량은 실제 할당량이므로 포함하고, 중복 count로 절약된 AVL 노드는 생성된 것으로 계산하지 않는다.

## 정확성 검사

시간 실험과 별도로 초기 정렬 후 및 각 삽입·삭제 직후 배열과 AVL 중위 순회의 원소를 모두 비교한다. 중복 개수, 오름차순, 모든 AVL 노드의 균형 인수와 저장된 높이도 검사한다. 검증 시간과 버퍼는 성능 집계에서 제외한다. 따라서 중위 순회로 정렬 상태를 확인하되 검증 비용 때문에 AVL 시간이 부풀려지지 않는다. 측정하는 AVL 정렬 결과는 트리 자체이고, 외부 출력 배열 생성 비용을 비교하는 실험은 아니다.

회전, 중복 후속 노드를 가진 삭제, 전부 삭제하여 빈 트리 만들기, 500회 작은 범위 임의 연산을 검사한다. 별도 빈도 배열을 정답으로 삼아 중복 개수 보존을 확인하며, 배열의 삽입·삭제·실패 탐색 비교와 이동의 정확한 횟수도 검사한다. 본 프로그램과 테스트 모두 컴파일·실행에 성공했다.

## 분석

### 전체 시간과 비교 횟수

1,000·2,000개에서는 AVL의 비교가 훨씬 적어도 배열이 더 빨랐다. 예를 들어 1,000개에서 배열 0.053320ms, AVL 0.102890ms였다. 배열은 연속 메모리를 단순 반복으로 처리하지만 AVL은 노드 할당, 포인터 탐색, 높이 갱신 및 회전을 수행한다. 비교 횟수에 포함되지 않는 이런 비용 때문에 작은 입력에서는 트리의 이점이 시간으로 나타나지 않을 수 있다.

4,000개부터 이번 측정에서는 AVL이 빨랐다. 20,000개에서는 배열이 AVL보다 약 4.26배 오래 걸리고 비교 횟수는 약 99.17배였다. 최초 정렬만 보면 배열은 317,880회, AVL 구축은 523,382회 비교했다. 그러나 후속 연산에서 배열 63,155,063회, AVL 116,683회가 추가되어 전체 순위가 바뀌었다. 초기 정렬만 비교하는 것과 변경을 포함한 전체 과정을 비교하는 것은 다른 문제다.

### 삽입·삭제 이동량

20,000개에서 초기 정렬 이동은 배열 551,870회, AVL 19,798회였다. 후속 연산 이동은 배열 20,622,985회, AVL 1,924회였다. 배열은 가운데 삽입 때 뒤 원소들을 한 칸씩 밀고 성공한 삭제 때 당긴다. AVL은 연결과 회전으로 구조를 바꾸므로 대량의 키 이동 없이 삽입·삭제를 수행한다. 중복은 count만 바꾸므로 키 대입이 발생하지 않는다. AVL의 총 이동 21,722회가 최종 서로 다른 노드 수와 반드시 같지는 않다. 삭제로 노드가 사라지거나 후속 키를 복사한 이력도 이동 합계에 남는다.

### 메모리 차이

20,000개 배열은 용량 24,000 × 4 = 96,000Byte에 퀵 정렬의 재귀 공간을 포함해 97,152Byte로 계산됐다. AVL은 최대로 21,661개의 노드가 동시에 존재했고 노드당 32Byte여서 노드만 693,152Byte, 재귀·보조 공간을 포함한 최대 추정은 693,672Byte였다. 배열보다 약 7.14배 크다. AVL의 왼쪽·오른쪽 포인터, 중복 개수, 높이와 패딩 때문에 정수 하나만 저장하는 배열보다 키당 공간이 크다. count는 중복 저장을 줄여 주지만 이번처럼 넓은 범위에서는 중복이 적어 절감 효과가 크지 않았다. 두 방법 모두 자료구조 자체를 포함하면 O(n) 공간이고 AVL은 더 큰 상수를 사용한다.

### 크기 증가와 적합한 환경

배열의 총 비교는 4,000→8,000에서 약 3.86배, 8,000→16,000에서 약 4.05배로 증가했다. 연산 횟수도 n의 20%로 함께 늘고 각 선형 탐색·밀기가 O(n)이므로 후속 작업이 O(n²) 규모로 증가한다. 최초 퀵 정렬의 평균 O(n log n) 비용보다 후속 연산이 지배한다.

AVL은 초기 n개 삽입과 0.2n개 변경 각각이 O(log n) 탐색·복구를 사용해 전체가 O(n log n) 규모다. 8,000→16,000에서 총 비교는 약 2.17배 증가했다. 16,000→20,000은 크기가 1.25배이므로 두 배 구간과 구별해야 한다. 최악 재귀 깊이가 O(n)일 수 있는 현재 퀵 정렬과 달리 AVL은 균형을 유지해 깊이를 O(log n)으로 제한한다.

삽입·삭제를 반복하며 정렬 상태를 유지해야 하고 메모리를 더 사용할 수 있다면 이번 조건에서는 큰 데이터일수록 AVL이 유리했다. 한 번 정렬하고 변경이 적거나, 작은 입력·연속 메모리·적은 공간이 중요하다면 배열이 적합할 수 있다. 배열 탐색을 이진 탐색으로 바꾸면 비교는 줄일 수 있지만 중간 삽입·삭제의 이동 O(n)은 남는다. 본 과제는 선형 탐색을 요구하므로 그 변경은 적용하지 않았다.

### 해석의 범위

값 범위가 0~1,000,000으로 넓어서 삭제 실패가 대부분이다. 특히 20,000개에서는 2,051회 중 42회만 성공했다. 따라서 결과는 삽입과 실패 삭제 탐색 비용을 크게 반영하며 성공 삭제가 많은 작업의 결과라고 해석하면 안 된다. 실패한 배열 삭제는 모든 값을 검사하고 AVL은 한 경로만 탐색한다. 실패 삭제에서는 이동이 없으므로 배열의 후속 이동은 주로 삽입에서 발생한다.

각 크기당 원본·연산 목록 하나의 결과이며 다른 난수 시드나 중복률, 삭제 성공률에서는 수치가 달라질 수 있다. 10회 평균은 시간 변동을 줄이기 위한 것이고 통계적 유의성을 검증한 것은 아니다. 모든 실제 연산 직후 데이터 구성·중복 개수·AVL 높이 및 균형 검사가 통과했다.
