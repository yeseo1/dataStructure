# 과제 14: 힙 정렬, 퀵 정렬 및 병합 정렬의 성능 비교

## 실행과 입력

`hw14.c`를 컴파일한다. 기본 시드 20261104와 크기별 `srand(seed+n)`을 유지하여 같은 C 라이브러리 환경에서 과제 13의 입력을 재현한다. 인자로 다른 시드를 지정할 수 있다. 값은 0~1,000,000이며 중복을 허용한다. 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000개 각각에 대해 새 원본 하나를 생성하고 다섯 방식에 같은 복사본을 준다.

## 구현과 비교 횟수

힙 정렬은 배열의 마지막 부모부터 반복형 `sift_down`을 적용하여 최대 힙을 구성한다. 루트와 마지막 원소를 교환한 후 힙 크기를 줄여 복구한다. 별도 힙 배열과 재귀 호출은 없다. 두 자식이 있으면 더 큰 자식을 결정하는 비교를 1회, 부모와 선택한 자식의 비교를 1회 센다. 힙 구성과 추출 후 복구가 같은 계수를 사용하므로 두 단계가 모두 포함된다. 비교 결과가 참인지와 관계없이 실제 실행한 비교를 센다.

병합 정렬과 세 퀵 정렬은 과제 13의 구현을 유지했다. 병합에서는 양쪽 원소의 `<=` 비교를 세며 한쪽이 소진된 후의 복사는 비교가 아니다. 퀵 정렬은 공통 Lomuto 분할과 First, Random, Median-of-Three 피벗을 사용한다. 분할의 `< pivot`과 중앙값 선택의 2~3회 값 비교를 모두 센다. 인덱스 검사, 난수 생성, 이동 및 검증은 비교 횟수에서 제외한다.

`qsort`는 검증 기준 배열을 만드는 용도로만 사용한다. 실험 정렬은 모두 직접 구현했으며, 결과를 기준 배열과 원소별로 비교하여 오름차순뿐 아니라 중복을 포함한 값의 보존도 확인한다.

## 실행시간 측정

Windows에서는 QueryPerformanceCounter를 사용해 ms로 측정한다. 다른 플랫폼의 대체 타이머는 clock의 CPU 시간이므로 플랫폼을 섞어 비교하지 않는다. 한 번 예열한 뒤 동일 입력을 100회 정렬해 평균을 출력한다. 다섯 방식의 실행 순서를 순환시켜 순서 영향을 줄인다. Random의 시드는 반복마다 재설정하여 동일한 피벗 선택을 재현한다. 이는 서로 다른 100개 입력의 평균이 아니다.

원본 생성, 배열 복사, 기준 결과 생성, 시드 재설정, 검증, 출력, 병합용 배열 할당은 측정 밖이다. 실제 병합용 복사, 힙 구성, 피벗 난수 생성, 비교 계수 갱신은 정렬 내부이므로 포함한다. 매 반복의 비교 횟수와 정렬 결과가 최초 실행과 같은지 검사한다.

## 최대 추가 메모리 계산 기준

메모리는 과제 13과 같은 소스 수준 저장량 모델의 추정값이며, 실제 실행 파일의 ABI 스택이나 프로세스 전체 메모리를 프로파일링한 값은 아니다. 원본·작업·검증 배열과 비교 계수·타이머 등 공통 실험용 상태는 제외한다. 알고리즘별로 필요한 공간만 따로 계산한다.

- 힙: `sizeof(HeapFrame)+sizeof(SiftFrame)+sizeof(SwapFrame)`. 힙 함수에서 sift-down과 swap을 호출하는 경로의 매개변수·지역 변수 공간을 모델링한다. 재귀가 없고 보조 배열도 없으므로 n에 무관하다.
- 병합: `n*sizeof(int)+D*sizeof(MergeFrame)`. 임시 배열은 한 번만 할당하여 모든 재귀가 공유한다.
- 퀵: `D*sizeof(QuickFrame)+helper`. helper는 `sizeof(PartitionFrame)+max(sizeof(PivotFrame)+max(sizeof(RandomFrame),sizeof(LessFrame)),sizeof(SwapFrame))`로 계산한다.

D는 별도 계측 실행에서 구한 최대 동시 재귀 호출 깊이이며 기저 호출을 포함한다. 출력에서 힙의 Depth=0은 **재귀 깊이**가 0이라는 의미로, 일반 함수 호출 공간은 위 식에 포함되어 있다. 시간 실험에서는 깊이 계측을 비활성화한다.

프레임 모델은 소스에 선언된 구조체의 sizeof로 계산해 패딩을 포함한다. 실제 ABI의 반환 주소·레지스터 저장·스택 정렬·shadow space, 컴파일러의 인라이닝·꼬리 호출 최적화, 라이브러리 내부와 할당기 메타데이터는 제외한다. 퀵의 helper는 기저 호출 깊이에 일괄 더하는 보수적 모델이며 실제 최고 동시 사용량과 정확히 같지는 않다. 따라서 이 값은 실제 스택 바이트의 실측이나 엄밀한 상한이 아닌, 동일 기준에서 알고리즘의 추가 저장량을 비교하기 위한 계산 추정이다. 병합용 배열은 시간 측정 전에 할당하지만 필수 공간이므로 메모리에 포함한다.

## 결과 분석

### 데이터 크기와 비교 횟수

힙 비교는 크기를 두 배 늘릴 때 약 2.18~2.24배 증가했다. 병합도 약 2.17~2.22배, 퀵도 대체로 두 배 전후의 증가를 보여 이번 무작위 입력에서는 O(n log n) 규모의 경향을 보였다. 마지막 16,000→20,000은 1.25배 증가이므로 두 배 구간과 구분해야 한다.

20,000개에서는 힙 510,633회, 병합 261,024회, 퀵은 317,880~343,437회였다. 힙은 병합의 약 1.96배를 비교했다. 힙 복구에서는 내려가는 각 레벨에서 큰 자식 선택과 부모 비교를 수행한다. 최대 힙을 구성하는 단계도 집계하며, 최댓값을 제거할 때마다 이를 반복한다. 병합은 균등하게 분할하고 한쪽 구간이 소진되면 나머지를 비교 없이 복사하므로 이번에는 모든 크기에서 비교가 가장 적었다.

### 실행시간

20,000개에서 힙 1.048147ms, 병합 0.797701ms, First 0.780057ms, Random 1.085179ms, Median3 0.792830ms였다. 힙은 병합보다 약 31.4% 길었다. 힙의 비교·교환이 많고 부모-자식 위치를 따라 접근하는 반면 병합은 연속 구간을 읽고 쓰므로, 비교 수와 메모리 접근 방식이 모두 시간에 영향을 줄 수 있다. 캐시 미스를 별도로 측정한 것은 아니므로 접근 방식의 영향은 구현에 근거한 해석이다.

힙이 항상 병합보다 느렸던 것은 아니다. 1,000개에서는 힙 0.026800ms, 병합 0.028238ms였다. 병합에는 임시 배열 쓰기와 원래 배열로의 복사 비용이 있다. 작은 입력에서는 이러한 비용과 측정 변동도 영향을 준다. 비교 횟수만으로 실행시간을 정할 수 없는 이유다.

Random은 힙보다 적게 비교했는데도 모든 크기에서 힙보다 시간이 길었다. 매 분할마다 두 번의 rand 호출과 범위 제한이 필요하며 이 작업은 비교 횟수에는 없지만 시간에는 포함된다. 다섯 방식의 순서를 순환하고 100회 평균을 사용했지만 분산이나 통계적 유의성을 계산하지는 않았으므로, 작은 차이를 일반적인 우열로 단정하지 않는다.

### 추가 메모리

실행 환경에서 HeapFrame=24, SiftFrame=32, SwapFrame=24Byte이므로 힙은 모든 크기에서 80Byte로 계산됐다. 입력 배열을 힙으로 재사용하고 sift-down도 반복형이므로 추가 공간 O(1)이다. 호출 스택을 아예 0으로 계산한 것이 아니라 일정한 함수 호출 경로의 명시적 변수 공간을 포함한 것이다.

병합은 1,000개에서 4,528Byte, 20,000개에서 80,768Byte로 증가했다. 20,000개는 임시 배열 80,000Byte + 최대 재귀 깊이 16 × MergeFrame 48Byte이다. 퀵은 같은 크기에서 First 1,152, Random 1,216, Median3 864Byte였다. 각각 깊이 33, 35, 24 × QuickFrame 32Byte에 보조 공간 96Byte를 더했다. 퀵은 입력 크기의 임시 배열이 없지만 재귀가 필요하고, 힙은 재귀도 없다는 차이가 드러났다. 이 숫자는 앞에서 정의한 모델의 추정값이다.

### 피벗과 복잡도

퀵만 비교하면 Median3이 6개 중 4개 크기에서 비교가 가장 적었고, 4,000·16,000개에서는 First가 적었다. 중앙값은 극단적 분할을 줄이는 데 도움이 되지만 선택 자체에 2~3회의 비교가 필요하다. 20,000개에서는 Median3이 First보다 25,557회 적게 비교했지만 시간은 First보다 조금 길었다. 분할의 모양, 분기, 선택 연산 등 여러 비용이 함께 작용한다.

| 알고리즘 | 평균 시간 복잡도 | 최악 시간 복잡도 | 추가 공간 |
|---|---|---|---|
| 반복형 힙 | O(n log n) | O(n log n) | O(1) |
| 병합 | O(n log n) | O(n log n) | O(n) 임시 배열 + O(log n) 스택 |
| 재귀형 퀵 | O(n log n) | O(n²) | 평균 O(log n), 최악 O(n) 스택 |

힙의 바닥부터 구성하는 단계는 O(n)이고, 추출과 복구를 반복하는 정렬 단계가 O(n log n)이다. 퀵의 First는 정렬된 서로 다른 값에서 편향될 수 있으며, 현재의 Lomuto 이분할은 모두 같은 값인 경우 세 피벗 방식 모두 편향된다. 이때 재귀 스택 한계도 문제가 될 수 있다. 병합은 값과 무관하게 반으로 나누고 힙은 완전 이진트리 형태를 유지하므로 최악 시간도 O(n log n)으로 제한된다.

추가 메모리를 작게 유지하면서 최악 시간도 보장하려면 힙이 적합하다. O(n)의 임시 공간을 허용하고 일정한 최악 성능을 원하면 병합이 적합하다. 이번 무작위 입력에서는 First 또는 Median3 퀵의 시간이 가장 짧았지만, 퀵은 입력과 피벗에 따른 최악 경우를 고려해야 한다. 각 크기당 원본 한 개를 사용했으므로 다른 분포·시드에서도 같은 순위라는 뜻은 아니다.
